# GitHub 研究／實作交接

GitHub 保存可接續的工作版本；K 槽提供同事閱讀。各目標獨立回報成功或待補同步，不把「已 commit」說成「已推送」。

## 可攜入口

- 先用 git 確認 repo 根目錄，再讀既有 README／AGENTS／PROGRESS 的文件入口。相對路徑隨 repo 版本管理，不依賴另一帳號的使用者目錄或 K 槽。
- 若既有入口不足，在本次文件預覽補上 Work Log、方法規格與研究／實作交接的相對連結；不建立第二套文件。
- GitHub repo、remote、工作分支與 upstream 從實際 Git 設定讀取。不假定 origin、main 或特定帳號；有多個合理目標時才請使用者選擇。
- K 槽 registry 的絕對路徑是發布裝置設定，不直接搬到另一台覆蓋其路徑。沒有 K 槽仍可記錄與推送。
- Skill 安裝本身不隨 repo 自動同步；另一裝置須安裝相同版本的 skill。必要交接資訊仍須存在 repo 文件，不只保留在聊天或本機 skill。

## 接續專案

1. 檢查工作樹、index、目前分支、upstream、Git 作者身分與既有認證；不輸出 token 或改寫全域帳號設定。Git 作者不等於遠端登入帳號，必要時分別確認。
2. 對已辨識的 remote fetch，檢查本地與遠端 ahead／behind。只有工作樹與 index 乾淨、目前工作分支有明確 upstream 且可快轉時，才更新到該分支遠端版本。
3. 未提交變更、detached HEAD、分支分歧或合併衝突時保留現況，回報差異與處理方式；不自動 stash、reset、覆蓋、切換分支或 force push。fetch 失敗時可讀本機進度，但註明遠端未確認。
4. 讀 PROGRESS 與相關 Log，說明研究狀態、實作狀態、待確認事項及可接續工作；交接指向實際工作分支與可用 commit。不要假定另一裝置正在同一分支。
5. 分支依任務建立或沿用。並行研究／實作可用不同分支；共享文件合併時保存雙方紀錄，同日項目去重，不用整份 ours／theirs 覆蓋。

## 收工提交與推送

預覽需列出 repo／remote／工作分支、明確檔案清單、變更摘要、提交目的及該分支所有既有未推送 commit。推送會發布整條尚未發布的歷史，不能只宣稱發布最後一個 commit。

確認寫入後：

1. 寫入本次確認的文件；檢查選定程式碼、notebook 與成果符合預覽。排除憑證、敏感 notebook 輸出、大型原始資料及無關變更。重現必要但不能提交的資料，記錄取得方式、版本與環境需求，不把資料缺失說成可完整重現。
2. 重新檢查 diff、index 與 remote 基準。僅 stage 明確路徑或已確認 hunks；不用 git add . 或 git add -A。同檔混有無關變更時分離確認範圍。若 index 原有他人 staged 內容，避免夾帶，也不擅自 unstage。
3. 按 repo 既有 commit 規範建立提交。無可提交差異時不造空 commit，檢查是否仍有已確認的提交待推送。
4. 推送明確 remote／工作分支，不附帶其他分支或 tag；不 force push。若遠端在預覽後前進導致拒絕，保留本地提交，重新取得差異、處理合併後再依變動範圍確認，不盲目重試。
5. 查驗遠端分支指向的 commit，附上 repo、分支與 commit 連結。網路或權限失敗則回報「本地已提交，GitHub 待推送」，不切換到另一帳號或 repo。
6. 執行 K 槽發布；無連線則回報待發布。GitHub 失敗不必阻止已確認文件發布 K 槽，但須標示兩邊版本差異。

若目前在主要分支，先在預覽確定任務分支，再依確認範圍建立。收工不自動建立 PR、合併主要分支或修改分支保護；正式交付依使用者當次授權與 repo 流程處理。

## 待確認方案與交接

- 研究可邊探索邊由實作端做原型。一般實作細節直接處理；改變訊號、資料口徑、回測、權重或交易規則的正式方法須先確認。
- Work Log 可在確認寫入後保存「待確認」方案，包含原因、實驗結果、影響及待回答問題。原型已完成不等於方法已採用。
- PROGRESS 可以寫「資料口徑待確認，原型完成」，並連到 Log；未確認方案不能列為已確認決策、正式方法或已成立結論。
- 交接只記錄有內容的研究／實作狀態、驗收依據與接手事項；不增加固定每日填表負擔。

## 補同步

- 「補同步 GitHub」只重試已確認的提交／分支；新增提交或範圍改變需更新預覽。
- 「補發布 K 槽」先取得要發布的已確認版本，核對目前文件沒有混入待確認內容，再依 mirror-contract 發布。
- 分支上的已確認進度可以發布 K 槽，不代表正式合併或交付；讀者須能辨識暫定與正式方法。
- 發布後回報來源 repo、分支、commit、K 槽目標與結果。不同分支的鏡像若已有更新而來源脈絡無法確認，先查清，不依日期或裝置角色逕行覆蓋。
